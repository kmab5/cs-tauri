# ChoiceScript Desktop Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Turn the ChoiceScript Vite front end into a native desktop application for macOS, Windows and Linux, with games and saves stored as real files on disk, a `.cszip` file association, Choice of Magics bundled, and an interface designed for a window rather than a page.

**Architecture:** Tauri v2 wraps the existing `dist/` build. Rust owns bytes and paths (archive extraction, file storage, the key/value store files); TypeScript keeps every piece of ChoiceScript semantics it already has. The web build keeps working: `src/lib/db.ts` becomes a runtime dispatcher between the existing IndexedDB backend and a new Tauri file backend. The interface splits into two visual registers — OS chrome and author's page — that theme independently.

**Tech Stack:** Tauri 2, Rust (`zip`, `flate2`, `tar`, `serde`), React 18, TypeScript 5, Vite 5, Tailwind 4, Radix, Motion, Sonner.

## Global Constraints

- **Tauri v2 only.** v1 config keys (`tauri.allowlist`, `tauri.bundle.identifier` at root) do not apply.
- **CSP must include `'unsafe-eval'`.** `engine/scene.js:2479` and `engine/util.js:1057` call `eval`; Choice of Magics uses `*script` three times. Removing it breaks published games silently.
- **`dragDropEnabled: false`** on every window, or Tauri swallows the drop event and `Library` stops accepting archives.
- **Never use `id="text"`.** Obligation 4 of the engine contract. The app renders into `.cs-text`.
- **Never modify files under `engine/`.** The bundle is generated by `scripts/build-engine.mjs` from those sources; changes belong in `src/` or in the store shim.
- **The web build must keep passing.** `npm run build && npm run test:theme && npm run test:e2e` stays green after every task.
- **Two registers.** Chrome uses `--app-*` tokens only. The reading surface uses `--cs-*` tokens only. Never cross them.
- **Reading themes never repaint chrome.** Chrome appearance follows the OS (light/dark/auto), not the selected reading theme.
- **Choice of Magics is licensed content.** It may sit in `src-tauri/games/` for a local build. Do not publish built installers containing it, and keep it out of any public release workflow.
- **Minimum window size 720×520.** Below 900 px wide the layout collapses to the existing single-column reading view.

### Task 1.2: Boot shims

- [ ] **Step 1: Write the detection and polyfills**


`crypto.randomUUID` is secure-context-only and `library.ts` uses it for every game id. Install a `getRandomValues` fallback that produces a v4 string. `DecompressionStream` is absent on WebKitGTK below 2.40; install a `TransformStream` that buffers chunks and calls a Rust `decompress` command on flush. ## Phase 4 — Save and store bridge

Deliverable: saves, achievements and per-game settings persist as JSON files and survive a restart.

### Task 4.1: File-backed `window.store`

**Files:** Create `src/lib/desktop/store.ts`; Modify `src/lib/desktop/index.ts`

The engine reaches persistence only through `window.store`, and `initStore()` (`engine/util.js:791`) returns any existing `window.store` rather than constructing one. So installing an object with the same three methods before `ChoiceScript.start()` is sufficient, with no engine changes.

**Interfaces:**
- Produces: `installFileStore(): void`, which sets `window.store` to

```ts
{
  get(key: string, fn: (ok: boolean, value: string | null) => void, scope?: unknown): void;
  set(key: string, value: string, fn?: (ok: boolean) => void, scope?: unknown): void;
  remove(key: string, fn?: (ok: boolean) => void, scope?: unknown): void;
}
```

- [ ] **Step 1:** Read `window.storeName` **per call**, not at construction. `initStore` caches `window.store` for the process lifetime while `openGame` reassigns `window.storeName` per game, so a cached namespace writes game B's saves into game A's file. Keying per call fixes a live bug in the web build too.
- [ ] **Step 2:** Hydrate lazily: the first operation for a namespace awaits `read_store`, then serves from an in-memory map. `set` updates the map, calls back immediately, and schedules a 200 ms debounced `write_store`.
- [ ] **Step 3:** Flush on exit — subscribe to `getCurrentWindow().onCloseRequested`, `await` the pending flush, then allow the close. Without this, the last save is lost when a player quits straight after saving.
- [ ] **Step 4: Verify persistence across a restart**

Play a few choices, save to a slot, quit, relaunch, restore. Then `cat stores/CS-<id>.json` and confirm the `state<slot>`, `savemeta_<slot>` and `achieved` keys are all there.

- [ ] **Step 5: Verify the namespace fix** — import two games, play both, confirm two separate store files.
- [ ] **Step 6: Commit** — `git commit -m "feat(desktop): file-backed engine store with per-call namespacing"`

## Phase 8 — The two registers

Deliverable: chrome that follows the OS, paper that follows the reader.

### Task 8.1: The `--app-*` register

**Files:** Create `src/styles/chrome.css`; Modify `src/index.css`

Today every token in `index.css` maps to `--cs-*`, so choosing a sepia reading theme repaints the window frame. In an app the frame belongs to the operating system and the page belongs to the author.

| Token | Purpose |
| --- | --- |
| `--app-chrome` | titlebar, sidebar, panel base |
| `--app-chrome-elev` | raised rows, hover states |
| `--app-border` | hairlines |
| `--app-label` / `--app-label-dim` | chrome text |
| `--app-accent` / `--app-accent-fg` | selection, focus |
| `--app-shadow` | panel elevation |
| `--app-titlebar-h` / `--app-control-h` | density |
| `--app-radius` | platform corner radius |
| `--app-font-ui` | platform UI stack |

- [ ] **Step 1:** Declare light and dark values under `:root` and `[data-appearance="dark"]`, set from `matchMedia('(prefers-color-scheme: dark)')` plus Tauri's theme change event, with a Light/Dark/Auto setting that defaults to Auto.
- [ ] **Step 2:** Platform UI stacks by `data-platform` — `-apple-system, "SF Pro Text"` on macOS, `"Segoe UI Variable Text", "Segoe UI"` on Windows, `Inter, Cantarell, "Noto Sans"` on Linux. The reading surface keeps the engine's serif families untouched.
- [ ] **Step 3:** Density — `--spacing-touch` stays 44 px under `@media (pointer: coarse)` and becomes 28 px for a mouse. WCAG 2.1 AA target size applies to touch; a 44 px toolbar button under a cursor just reads as a tablet app.
- [ ] **Step 4:** Thin overlay scrollbars, `scrollbar-gutter: stable`.
- [ ] **Step 5:** Toasts move to a bottom-right stack, capped at three. With 325 `*achieve` calls in the bundled game, the cap matters.
- [ ] **Step 6: Verify** — switch reading theme through all six; the sidebar, titlebar and dialog frames must not move. Switch the OS between light and dark; the chrome must follow while the page does not.
- [ ] **Step 7: Commit** — `git commit -m "feat(desktop): split chrome and page into separate token registers"`

### Task 8.2: Vibrancy

**Files:** Modify `src-tauri/src/lib.rs`, `src/styles/chrome.css`

- [ ] **Step 1:** Apply effects at runtime per platform rather than in config, since an unsupported effect errors: `sidebar` on macOS, `mica` on Windows 11, nothing on Linux and older Windows.
- [ ] **Step 2:** Only chrome surfaces get translucency. The reading column stays fully opaque — prose over a blurred desktop is unreadable, and the whole design brief is that the page recedes.
- [ ] **Step 3:** Provide an opaque fallback for every vibrancy surface, since Linux never gets one.
- [ ] **Step 4: Verify** on macOS and Windows 11; confirm the Linux build looks intentional rather than flat.
- [ ] **Step 5: Commit** — `git commit -m "feat(desktop): platform vibrancy on chrome surfaces only"`

### Task 8.3: Register guard

**Files:** Create `scripts/check-register.mjs`; Modify `package.json`

The repo already carries `check-theme-scope.cjs` because the `:root` scoping bug was introduced twice. The two-register split creates the same class of trap: a `--cs-` token in a chrome component compiles fine and only looks wrong once someone picks a different reading theme.

- [ ] **Step 1:** Parse the built stylesheet plus the chrome components; fail if `--cs-` appears in a chrome selector or `--app-` appears under `.cs-text`.
- [ ] **Step 2:** Add it to `npm test`.
- [ ] **Step 3: Verify** — deliberately put `var(--cs-accent)` in `Sidebar.tsx` and confirm the build fails.
- [ ] **Step 4: Commit** — `git commit -m "test: guard the chrome and page register split"`

## Self-review

**Spec coverage.** File storage → Phases 2–4. `.cszip` association → 5.2. Bundled Choice of Magics → 5.1. Native theming rethink → 6, 7, 8. Desktop-only targets → 1.1 bundle list. Every design decision from the approved spec maps to a task.

**Known risks.**

1. Asset protocol scope. `$APPDATA/**` should cover the game directories, but if `convertFileSrc` returns a URL the webview refuses, all 73 images in the bundled game break at once. Task 3.1 Step 5 checks this before Phase 5 depends on it.
2. `windowEffects` behaviour varies by OS version. Task 8.2 keeps effects at runtime and behind a fallback for exactly this reason.
3. The web `check-theme-scope` guard and the new register guard could disagree about a shared token. If they do, the register guard yields; the older one is protecting a bug that has already happened twice.

**Ordering note.** Storage lands before the interface work because Phases 6–8 would otherwise be rebuilt on top of a changing data layer. The overlap is small — `Library.tsx` is touched by both — so if you would rather see the native shell sooner, Phases 6 and 8 can move ahead of 3 and 4 at the cost of one merge in that file.
